# Step 2: Assess Data

Now that we have gathered the datasets, let's assess them for **data quality and structural (tidiness) issues**. This step is essential to ensure that the datasets are ready for cleaning and eventual analysis.

## Data Quality Pillars

Here is a list of key data quality pillars to assess in each dataset:

- **Completeness**: Are there missing values in critical variables that could affect analysis?
- **Validity**: Do the data values fall within acceptable ranges or formats?
- **Accuracy**: How well do the data values reflect real-world truth?
- **Consistency**: Are data points consistent within and across datasets?
- **Uniqueness**: Are there duplicate records that may distort analysis?

## Data Tidiness Rules

In addition to data quality, evaluate the datasets for **tidiness**. Here are the three essential rules of data tidiness:

1. **Each variable forms a column**: Each unique variable in the dataset should be in its own column.
2. **Each observation forms a row**: Each individual data observation should have its own row.
3. **Each type of observational unit forms a table**: Different types of data (e.g., customers and products) should be in separate tables unless they are directly related.

**Note 1**: Ensure that any issues found are truly related to quality and tidiness. Concepts like feature engineering and dimensionality reduction, which focus on data transformation, do not count as data quality or tidiness issues.

- **Feature Engineering**: This process involves creating new variables or transforming existing ones to improve analysis, such as deriving additional insights or making data more suitable for modeling. For example, generating an "age" variable from a "date of birth" field or creating aggregated variables is part of feature engineering. **Feature engineering is not considered a data quality or tidiness issue**.
- **Dimensionality Reduction**: This process reduces the number of variables in a dataset, often to simplify analysis or improve model performance. In this project, dimensionality reduction will be addressed separately when you remove irrelevant variables as required in the project rubric. **It does not count as a data quality or tidiness issue**.

**Note 2**: The fact that you need to merge the datasets indicates the data structure violates the third data tidiness rule: **Each type of observational unit forms a table**. You may include this issue in your notebook and identify just one more data tidiness issue.
