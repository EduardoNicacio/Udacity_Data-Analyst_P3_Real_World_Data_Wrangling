## 1. Elevator Pitch

**The Problem:** Does GDP per capita reliably predict national happiness, and has that relationship changed between 2015 and 2019 across world regions? Answering it requires two related datasets that are individually messy: the World Happiness Report ships as five separate yearly CSV files (2015–2019) whose column names drift between editions, whose country names disagree with economic sources, and which carry at least one missing value; the World Bank provides GDP per capita for the same years through a paginated JSON API, using its own country-name conventions.

**The Solution:** An executed Jupyter notebook gathers both datasets with two different methods - programmatic file download with `requests` (five raw CSVs saved to `data/raw/`) and API access with JSON parsing (`NY.GDP.PCAP.CD`, 2015–2019) - then assesses and cleans four documented issues (two quality, two tidiness), removes unnecessary variables, and merges happiness with World Bank GDP on `Country` + `Year`. Every cleaning step is validated programmatically with assertions, and both raw and cleaned versions are retained in the data store.

**The Result:** The raw inputs are **782 country-year observations** across five happiness tables and **1,330 API records** (266 named economies). After cleaning - one missing corruption value imputed (United Arab Emirates, 2018, median 0.082), 31 country-name mismatches mapped (161/167 spellings matched exactly, 96.4%), five tables concatenated into one with a `Year` column, and 30 divergent column spellings unified to a canonical schema - the final merged dataset is **782 rows × 12 columns with 97.8% World Bank coverage**. The analysis finds that GDP per capita is a real but decelerating happiness predictor: 2019 Pearson **r = 0.74** (Spearman 0.84), yet beyond roughly $40k per capita the trend flattens - Luxembourg, the richest country at $112,697, scores only 7.09. Between 2015 and 2019, happiness gains concentrate in Central and Eastern Europe (+0.23) and Western Europe (+0.15), while Latin America (−0.19), North America (−0.19) and the Middle East and North Africa (−0.17) decline - so income growth translates into happiness mainly at lower income levels.

### Key Design Decisions

| Decision | Rationale |
| :--- | :--- |
| **Verify data sources before writing the gather cells** | The suggested `dsrscientist/dataset1` mirror returned 404 for every file. I listed candidate repos through the GitHub API, tested raw URLs, and confirmed each mirror file's header matched the authentic Kaggle schemas (including 2017's dotted names) before committing to it - so the download cell in the notebook is guaranteed to work. |
| **Keep raw data truly raw; clean only on deep copies** | Raw CSVs are written byte-for-byte as received, and `copy.deepcopy` guards every dataframe used by cleaning cells. The combined "raw" file (`happiness_all_years_raw.csv`, 782 × 31) preserves every original column spelling - its 31 columns are the tidiness problem made visible. |
| **Resolve column aliases before the canonical rename** | The missing-value step runs before the rename, so `dropna` and the corruption imputation search candidate names (`Happiness Score` / `Happiness.Score` / `Score`, and three corruption spellings) instead of assuming one. This prevents a silent no-op on the 2017 file. |
| **Rename before concatenating, and make it idempotent** | `pd.concat` aligns columns by name, so the canonical rename is a structural prerequisite of the merge - it is applied inside the Tidiness Issue 1 fix and re-applied in the Tidiness Issue 2 cell so each fix stands alone. An assert then proves no legacy spelling survives. |
| **Curated country mapping plus a conservative fuzzy fallback** | 26 known mismatches are handled deterministically (auditable, reproducible). `difflib.get_close_matches(cutoff=0.75)` covers residual cases - deliberately conservative, because Ireland/Iceland-style pairs score ~0.71 and would be false positives at a looser cutoff. |
| **Do not fabricate missing GDP** | Taiwan, North/Northern Cyprus and the Somaliland regions are not reported as separate economies by the World Bank; South Sudan (2016–2019) and Yemen (2019) have no figure. Those 17 rows keep a `NaN`, are reported in the merge-quality printout, and are excluded only from the scatter - never imputed from a lookalike country. |
| **Left join + explicit coverage metric** | The left join guarantees all 782 happiness observations survive (asserted), and the 97.8% coverage figure is printed so the audience knows exactly how much of the visual evidence rests on matched data. |
| **Ground every prose number in an executed output** | The slope, correlations, merge rate and regional deltas quoted in the narrative were read back from the executed notebook cells - not estimated - and the prose was corrected where it disagreed. |

## 3. Analytical Principles in Practice

**Assess before cleaning, both visually and programmatically.** Each of the four issues gets a visual assessment (null-value heat maps, side-by-side country spellings, shape table, printed column lists) and a programmatic one (`isnull().sum()` counts, set differences, `Year`-column/index probes, set union/intersection), with the justification for each method written down.

**Treat tidiness as structure, not cosmetics.** The five year-files violate "each type of observational unit forms a table," and the drifting column names violate "each variable forms a column." Both are fixed structurally - one `Year` column derived from the file name, one canonical schema - rather than by renaming columns ad hoc during analysis.

**Validate each cleaning step before moving on.** Every clean cell is followed by a validation cell: completeness assertions after imputation, a re-run of the set difference after country alignment, row-count assertions after concatenation, and legacy-name assertions after the rename. The final combine step asserts ≥ 4 columns and that the left join dropped no rows.

**Report merge quality instead of trusting the join.** A left join can hide mismatches as silent `NaN`s, so the combine cell prints the coverage rate and enumerates the unmatched countries. That single number (97.8%) qualifies every downstream claim.

**Keep association and causation apart.** The visuals show that richer countries are happier and that regional trajectories diverge; the written answers say explicitly that GDP is an incomplete, region-dependent predictor and that the 2015–2019 deltas are descriptive - not estimates of what growth *caused*.

**Let the data contradict the story.** The scatter's flattening at high income (Luxembourg: $112,697 → 7.09) and Latin America's happiness *decline* during the period are reported as-is, because they are the strongest evidence that GDP alone is not a sufficient predictor.

## 4. AI Collaboration Playbook

The deliverable was an executed notebook whose every claim had to match its own outputs, so the workflow was built around an evidence hierarchy: **source files → executed cells → prose**.

The workflow was:

1. Prototype the entire pipeline as a throwaway script first, to surface real data quirks (the 2017 dotted column names, the 2018 missing value, the 31 country mismatches) and to pre-compute every number the prose would need.
2. Write the notebook cell-by-cell against the starter template, keeping raw/assess/clean/validate/combine sections in rubric order, with inline `#` comments on every code cell.
3. Execute top-to-bottom with `jupyter nbconvert --execute --inplace`, then read the *executed* outputs back and reconcile the written answers against them - correcting a wrong slope figure ("3.9e-05" → 3.8e-05), a wrong name count (167 → 170), wrong column-set counts (24/8 → 30/1), and a print bug that paired Luxembourg's GDP with the global maximum happiness score.
4. Treat toolchain quirks as bugs to diagnose, not noise: a PowerShell exit-code artifact was disproved by re-running through `cmd` (`EXIT=0`), and a notebook-cell collapse was traced to `nbformat` joining source lines that lacked trailing newlines.
5. Rebuild the notebook from its generator scripts and re-execute after every fix, so the committed file is always a clean full run rather than a patched partial state.

The key collaboration principle is **reconcile, don't assert**: prose never gets to overrule an executed output, and every fix is verified by a fresh end-to-end execution rather than by inspection alone.

## 5. Evaluation & Verification Philosophy

**Executed outputs are the evidence.** All reported figures - 782 rows, 1,330 API records, 96.4% name-match rate, 97.8% merge coverage, r = 0.74, the regional deltas - were read from the executed notebook, not from estimates or documentation.

**Assertions are quality gates, not decoration.** The notebook asserts completeness after imputation, the residual-unmatched count after name alignment, per-year row totals after concatenation, absence of legacy column names after the rename, ≥ 4 final columns, and that the left join preserved all 782 observations. A green run means those properties held *this* run.

**Check denominators alongside every percentage.** Coverage is reported as "97.8% of 782 rows" with the 17 unmatched country-years listed by name; correlations are reported with n = 152; name alignment is reported as 161/167, not as a bare percentage.

**Raw and cleaned are different artifacts on purpose.** The raw store (including the 31-column un-cleaned combined file) lets a reviewer reproduce or re-run any cleaning decision against the original bytes; the cleaned store is the analysis table. Descriptive file names make the version boundary obvious.

**Missing data is disclosed, not papered over.** The 34 null GDP values and 17 unmatched country-years stay `NaN` and are enumerated - imputing a GDP figure from a neighboring country would manufacture evidence for the very relationship being tested.

**The rubric is a checklist, not a substitute for reading the outputs.** The final review below re-checked every rubric criterion against the executed file (code runs without errors, two gathering methods with >500 samples each, four issues assessed and cleaned with justifications, ≥ 4 combined variables, two explained visuals, 2–4 sentence reflection, no `FILL IN` tokens) rather than assuming completion from the build scripts.

## 6. Challenges & Resolutions

### Challenge 1 - The suggested data mirror did not exist

**What happened:** The instructed fallback URL (`raw.githubusercontent.com/dsrscientist/dataset1/master/happiness_2015.csv` … `_2019.csv`) returned **404** for every file, and a repo listing confirmed the repository contained no happiness files at all. Writing the gather cell against it would have produced a notebook that fails on first run.

**Resolution:** I enumerated candidate repositories through the GitHub API, tested raw URLs, and verified that all five files in the chosen mirror resolve **and** match the authentic Kaggle headers for each edition (2015–2016 `Trust (Government Corruption)`, 2017 dotted names, 2018–2019 `Country or region`/`Score`). Only then was the download cell written, with `raise_for_status()` so any future source failure fails loudly instead of silently caching an error page.

### Challenge 2 - Column names changed between report editions

**What happened:** The five files share only **one** verbatim column name (`Generosity`) among **30** distinct spellings: `Score` vs `Happiness.Score` vs `Happiness Score`, `Country or region` vs `Country`, `GDP per capita` vs `Economy..GDP.per.Capita.` vs `Economy (GDP per Capita)`, and three spellings of the corruption variable. The trap is ordering: the missing-value fix runs *before* the canonical rename, so a naive `dropna(subset=["Happiness Score"])` would crash on the 2017 file.

**Resolution:** Cleaning cells resolve columns through alias lists (`SCORE_ALIASES`, `CORRUPTION_ALIASES`, `COUNTRY_ALIASES`) and a `pick_column` helper, so every step is edition-agnostic. The canonical rename (16 alias mappings) is applied as a prerequisite of `pd.concat`, re-applied idempotently under its own issue heading, and validated by asserting that no legacy spelling survives in the combined table.

### Challenge 3 - Country names differ between the two sources

**What happened:** **31 of 170** happiness country spellings have no verbatim match in the World Bank list - systematic differences (`United States` / `Russia` / `South Korea`), World Bank punctuation forms (`Gambia, The`, `Congo, Dem. Rep.`), and renames over the period (`Swaziland` → `Eswatini`, `Turkey` → `Turkiye`). Every unmatched country would become a silent `NaN` after the merge.

**Resolution:** A curated 26-entry mapping dict handles all known pairs deterministically, followed by a `difflib.get_close_matches` fallback at a conservative **0.75** cutoff (chosen because Ireland/Iceland-style pairs score ~0.71 and would be false positives). Validation re-runs the set difference: **161/167 (96.4%)** match exactly, and the six remaining names - Taiwan (×2 spellings), North/Northern Cyprus (×2), Somaliland (×2) - are left deliberately unmatched because the World Bank does not report them as separate economies. Fabricating those matches would have invented GDP evidence for the relationship under test.

### Challenge 4 - 17 country-years have no World Bank GDP figure

**What happened:** Even after name alignment, the left join leaves **17 of 782 rows** (2.2%) without `wb_gdp_per_capita`: the five non-reporting entities above plus **South Sudan (2016–2019)** and **Yemen (2019)**, where the API genuinely returns no value for those years.

**Resolution:** Those rows are kept in the dataset (the left join preserves all observations - asserted), the coverage rate and the full unmatched-country list are printed at merge time, and the scatter simply drops them with `.dropna()` while stating n = 152. The limitation is carried into the reflection as the first improvement to pursue with an alternative source (IMF WEO) rather than being hidden or imputed.

### Challenge 5 - Notebook source lines collapsed during patching

**What happened:** Patch scripts rebuilt edited cells by splitting source text on `"\n"` without keeping trailing line endings. `nbformat` normalization later joins source lists with `""`, which silently collapsed two code cells into a single syntactically invalid line - and a failed re-execution wrote a partial notebook back over the good one, so the corruption survived one review cycle.

**Resolution:** Both patch helpers were rewritten to emit standard nbformat line endings (every line but the last ends with `\n`), the notebook was rebuilt from its generator scripts end-to-end, and the full chain was re-executed with `cmd` to obtain the true exit code (`EXIT=0`). The final verification confirms sequential execution counts for all 24 code cells, zero error outputs, and zero warning outputs.

## 10. Retrospective

### What I'd Do Differently

1. **Join on ISO-3 codes instead of country-name dictionaries.** The World Bank country metadata exposes stable codes; fetching them at gather time would make the 26-entry curated map, the fuzzy fallback and its residual six non-matches unnecessary - and would eliminate the risk that a future edition renames a country we do not know about yet.
2. **Backfill the 17 missing GDP figures from a second economic source.** The IMF WEO API covers South Sudan and Yemen where the World Bank extract does not, which would lift scatter coverage from 97.8% toward 100% without inventing anything.
3. **Model the flattening instead of only drawing it.** A log-GDP or piecewise fit would quantify the diminishing-returns shape that the linear polyfit only hints at, and comparing GDP against `Social support` and `Health (Life Expectancy)` - already cleaned in the same table - would test which factor actually predicts happiness best.
4. **Extend the window and add sensitivity checks.** Adding pre-2015 and pandemic-era years, plus an alternative treatment of the single imputed value (dropping vs. median vs. regional median), would show whether the regional trends survive methodological choices rather than depending on one cleaning path.

### What Worked Well

1. **Prototyping the whole pipeline before writing the notebook.** The throwaway script surfaced the real data quirks (2017 dotted names, the 2018 gap, 31 mismatches) and pre-computed every statistic the prose would quote - so the notebook was written once, not reworked.
2. **Evidence-first prose.** Every number in the narrative was read back from executed outputs and corrected when it disagreed - four concrete corrections in the first reconciliation pass.
3. **One clean + one validate cell per issue, with assertions.** The validation cells are executable proof, not prose claims; a green run means the issue is really gone.
4. **Alias-aware cleaning helpers.** `pick_column` with edition-specific alias lists made every cleaning step robust to the column drift *before* the canonical rename existed.
5. **Diagnosing toolchain quirks instead of papering over them.** The PowerShell exit-code artifact and the `nbformat` source collapse were both root-caused (re-run through `cmd`; standard line endings) rather than retried blindly - which is why the final file is a genuine clean run.
6. **Disclosing merge coverage and the unmatched countries.** Printing 97.8% with the full list keeps the limitation visible in the same cell that reports the success.

### The AI Partnership

> "The value of AI in this project was not to generate a plausible-looking notebook; it was to hold the whole chain accountable - source URLs, data quirks, cleaning order, executed outputs and written claims - and to reconcile them until they agreed. The prototype-first approach turned hidden data problems into known ones before any prose was written, and the evidence-first rule meant the narrative was corrected four times rather than the outputs being trusted because they were convenient. The human role was to demand real verification (true exit codes, actual source-line integrity, rubric-by-rubric review) and to keep the honest limitations visible: six countries the World Bank does not report, 17 missing GDP figures, and findings that are association, not causation. AI accelerated execution and drafting; it did not get to decide what the data meant."

### Final Thoughts

This project demonstrates the core discipline of real-world data wrangling: gather from two different sources with different methods, assess every issue both visually and programmatically, clean with written justification, validate each fix, and keep raw and cleaned data apart. The result - a 782-row tidy table joining happiness with independent GDP figures - answers the research question with proportionate confidence: GDP per capita is a genuine but decelerating predictor of national happiness (r = 0.74 in 2019), and the 2015–2019 regional trajectories show its gains concentrated where income was still rising, not where it was already high.

The most important engineering lesson is the same one the data taught: **every join is a claim.** A name mismatch, an unreported economy or a null API value becomes a silent `NaN` unless the pipeline prints its coverage and lists what it could not match. Keeping those 17 rows visible - and the six deliberately unmatched countries honest - is what makes the 97.8% trustworthy rather than merely high.
